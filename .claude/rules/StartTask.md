# Project Workflow (MANDATORY)

These steps are REQUIRED for every task.

## Before starting any task

1. Read `CLAUDE.md` completely.
2. Understand the project's:
   - architecture
   - coding conventions
   - workflow
   - constraints
   - current project context
3. If `CLAUDE.md` references additional documents, read those before proceeding.
4. Do NOT start implementing until you understand the project context.

## During implementation

- Follow every rule defined in `CLAUDE.md`.
- If a conflict exists, `CLAUDE.md` takes precedence over your default behavior.
- Do not ignore or override project conventions.

## After completing the task

Before considering the task complete:

1. Review whether new knowledge should be added to `CLAUDE.md`, including:
   - architecture changes
   - new conventions
   - important implementation decisions
   - reusable patterns
   - common pitfalls
   - new commands or workflows

2. Update `CLAUDE.md` if necessary.

3. Keep `CLAUDE.md`:
   - concise
   - organized
   - free of duplicate information

A task is NOT considered finished until the project documentation has been reviewed and updated when appropriate.

## Documentation

At the end of every task, evaluate whether `CLAUDE.md` needs updating.

Only update it when one of the following has changed:

- project architecture
- coding conventions
- development workflow
- repository structure
- reusable implementation patterns
- important decisions affecting future work

Do NOT update `CLAUDE.md` for:
- one-off bug fixes
- temporary workarounds
- task-specific implementation details
- generated code
- information already documented
